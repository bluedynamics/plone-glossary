## Documented limits, for the package documentation

One or two sentences per limit, for readers of the package documentation.

- B1: Each text run is matched on its own. A term split by formatting (part of the word bold) is not found, and the first part of a word split by formatting can be marked as a term of its own.
- B4: Large glossaries work, but marking a page takes longer with more terms: about 0.1 seconds for 5000 terms and 300 text runs on a current laptop. A term longer than 32,767 characters is left out.
- B5: Terms in hidden content (a closed accordion, an inactive tab) get tooltips like visible ones. With `matchOnlyFirstOccurrence` the first occurrence may be such a hidden one, and the visible occurrences of the term then have no tooltip.
- B12: If the terms cannot be loaded, the page shows plain text; they are requested again on the next change of the navigation root, not in a loop.
- B14: Pages whose path contains a Volto CMS route name followed by more characters, for example `/de/sharing-economy` or `/de/contents-overview`, get no tooltips, because Volto treats them as CMS pages.
- C2: The package notices changes it makes through React. When other code moves, wraps or adds text in the page, tooltips follow only at the next change of the page's occurrences.
- C8 (R45): A double click on a term opens and closes its popover and selects no word. Select a term by dragging or with the keyboard.
- C14: The text leaf wraps every Slate text run in `<span class="">`. The rich text widget stores this wrapper in the saved HTML, as Volto already does for bold or italic text.
- C16: An add-on loaded after this one that puts its own Slate leaf before the text leaf takes the text first; text runs with its mark then get no tooltips. Add-ons that append their leaf are not affected.
- C23: Clicking the letter that is already in the address bar moves the focus to its heading after the browser's own jump; this relies on the browser jumping within the same task, which holds in current Chromium and Firefox.
- FC1: Browsers without regular expression lookbehind (Safari before 16.4) show no tooltips; the page works.
- FC2: In Chinese, Japanese, Thai and other scripts written without spaces, a term inside running text is not found.
- FC3: Case-insensitive matching uses simple case folding: `Straße` does not match `STRASSE`, Turkish `İ` does not match `i`.
- FR1: With `matchOnlyFirstOccurrence`, terms that differ only in case (EMS and Ems) count as one term; only the first of them gets a tooltip.
- FR2: Terms inside content marked `aria-hidden="true"` still become focusable triggers. Mark such content with `data-glossary="off"`.
- FR3: With `matchOnlyFirstOccurrence`, if content above loads later and holds an earlier occurrence of a term whose popover is open, the popover closes and the keyboard focus goes back to the start of the page.
- FR5: In a popover opened by click or key press, Tab moves only inside the popover. Press Escape to close it and continue after the term.
- FV3: The package needs the `navroot` API expander of Volto's default configuration. Without it every page counts as the site root, and terms of all languages get tooltips.

## Decisions for Jens

### Default of `matchOnlyFirstOccurrence` (B10, C24)

Measured on the acceptance page: off 26 tab stops (6 triggers), on 23 (3 triggers). The difference grows with the length of a text and the frequency of its terms.

Recommendation: keep the default off.
Every occurrence is explained where the reader meets it, which matters for readers who do not start at the top (a link to a section, a screen reader user who jumps by heading, a long page read in parts).
Three limits exist only with the setting on: a hidden first occurrence takes the only trigger (B5), terms that differ only in case count as one (FR1), and an open popover can lose its occurrence when content loads above (FR3).
Extra tab stops do not fail a WCAG criterion; a project with long texts and frequent terms can turn the setting on, and the documentation should say when that helps.

## Decisions for the controller

### C14: the empty span in stored rich text

The fix that would keep `<span class="">` out of the HTML stored by `HtmlSlateWidget` needs the text leaf to read React context (`useContext(ReactReduxContext)`) and return the plain string when there is no store with this package's reducer.
That contradicts the F5 regression test in `src/volto/slate.test.tsx`, which calls the leaf as a plain function a varying number of times inside one component and fails on React's warning about a changed order of hooks.
Not done, as the task asks to stop and report such a conflict.
Recommendation: accept it as a documented limit. Volto already stores the same wrapper for every marked text run, the wrapper carries no attribute value, and volto-slate's `spanTagDeserializer` turns a span without style back into plain text when the HTML is loaded into the editor, so the wrapper does not nest with each save (read in `core/packages/volto-slate/src/editor/deserialize.js`, not run). Changing the leaf would trade a cosmetic difference in stored HTML for a hook in a function that other renderers may call outside a component.
